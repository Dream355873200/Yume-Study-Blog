## 1. 编译型语言和解释型语言

老师介绍了编译型语言和解释型语言的区别，这是理解编译原理的基础。

### 编译型语言

源代码经由编译器**一次性翻译**成可执行程序，之后数据输入执行代码产出 output。

```text

┌─────────────┐      ┌──────────────┐      ┌─────────────┐

│   源代码    │ ──→  │    编译器    │ ──→  │  可执行程序  │

└─────────────┘      └──────────────┘      └─────────────┘

                                                  │

                                                  ↓

                     ┌──────────────┐      ┌─────────────┐

                     │   输入数据   │ ──→  │   Output    │

                     └──────────────┘      └─────────────┘
```

### 解释型语言

数据和源代码**同时**经过解释器产出 output。
```text
┌─────────────┐

│   源代码    │ ──┐

└─────────────┘   │      ┌──────────────┐      ┌─────────────┐

                  ├──→   │    解释器    │ ──→  │   Output    │

┌─────────────┐   │      └──────────────┘      └─────────────┘

│   输入数据  │ ──┘

└─────────────┘
```

### 核心区别

这就是两个最大的区别：

- **编译型语言**：编译完成后就和编译器无关了，直接运行机器码，速度快
- **解释型语言**：需要由解释器实时编译语言执行，更灵活但运行较慢

## 2. 编程语言历史


二十世纪 IBM 开发出计算机后，人们发现一个问题——**软件开发成本甚至比硬件还贵**,所以便利地开发软件成为了当时非常重要的需求。

于是出现了第一个解释型语言 **SpeedCoding**。但由于解释型语言的特性，它存在两个致命问题：

- 解释器本身占了大概 **300 bytes** 的内存（当时这是很大的空间）
- 运行速度很慢（大概比手写汇编慢 10-20 倍）

所以急需开发出新的编译型语言，于是 **FORTRAN I** 应运而生（1957 年），很好地解决了这些问题，也开启了现代编程语言的时代。

## 3. 代码编译的五个步骤

编译器的工作可以分成以下几个阶段：

| 阶段  | 名称                           | 做什么                                   |
| --- | ---------------------------- | ------------------------------------- |
| 1   | **词法分析** (Lexical Analysis)  | 把源代码拆分成一个个 token（词法单元），比如关键字、变量名、运算符等 |
| 2   | **语法分析** (Parsing)           | 根据语法规则，把 token 组织成语法树（AST），检查代码结构是否正确 |
| 3   | **语义分析** (Semantic Analysis) | 检查语义是否合理，比如类型检查、变量是否声明等               |
| 4   | **优化** (Optimization)        | 在不改变程序行为的前提下，让代码跑得更快、占用更少资源           |
| 5   | **代码生成** (Code Generation)   | 把优化后的中间表示翻译成目标机器码或汇编代码                |

```text
源代码 → 词法分析 → 语法分析 → 语义分析 → 优化 → 代码生成 → 目标代码
```


## 4. 编程语言经济学

老师提了一个很有意思的问题：**为什么会有这么多编程语言？**

### 不同领域，不同需求

| 领域         | 代表语言                    | 核心诉求                 |
| ---------- | ----------------------- | -------------------- |
| **科学计算**   | FORTRAN, MATLAB, Python | 数值计算性能、丰富的数学库、易于表达公式 |
| **商业应用**   | COBOL, Java, C#         | 稳定性、可维护性、处理大量数据和事务   |
| **系统开发**   | C, C++, Rust            | 底层控制、内存管理、极致性能       |
| **Web 开发** | JavaScript, PHP, Go     | 快速开发、灵活性、生态丰富        |
| **人工智能**   | Python                  | 快速原型、数学表达、社区支持       |

### 新语言是怎么诞生的？

新语言的出现通常遵循这样的逻辑：

```text

┌──────────────┐      ┌──────────────┐      ┌──────────────┐

│  现有语言的  │ ──→    │  新的应用场景 │ ──→   │  新语言诞生  │

│  痛点/局限   │       │   或技术趋势  │       │              │

└──────────────┘      └──────────────┘      └──────────────┘
```

就像这几种的演化：

- **C → C++**：需要面向对象，但又不想放弃 C 的性能
- **Java → Kotlin**：想要更简洁的语法和更好的空安全
- **JavaScript → TypeScript**：大型项目需要类型检查
- **C++ → Rust**：想要内存安全但不想要垃圾回收
- **C++ → Golang**:需要编译速度和便捷的并发

 而且旧语言随着用户量的增大，
 
 它的更新速度为了用户学习成本的考量就会减慢，
 
 而且会由于兼容过去导致难以拥抱新特性导致**负债累累**，就像现在的C++
