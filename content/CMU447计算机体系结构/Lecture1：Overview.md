## 一、架构师的类比：Fallingwater

老师用建筑师 Frank Lloyd Wright 设计的 **Fallingwater（流水别墅）** 来类比计算机体系结构。

这个类比挺好，建筑架构师和计算机架构师都需要具备这样的特点（毕竟都是架构师）：

- **理解材料/硬件的特性**

## 二、一个有趣的实验：GCC 和 MATLAB

### 实验现象

老师展示了一组很有意思的对比数据：

|运行方式|MATLAB 减速比|GCC 减速比|
|---|---|---|
|单独运行|1.0 (基准)|1.0 (基准)|
|一起运行|**1.07**|**3.04**|

这就很奇怪了：**为什么 GCC 慢了整整 3 倍，MATLAB 却几乎没影响？**

### 答案：内存控制器在"偏心"

这就引出了 **DRAM 原理**和**内存控制器调度**的话题。

#### DRAM 的 Row Buffer 机制

简单说，DRAM 里有个叫 **Row Buffer（行缓冲）** 的东西：

- **命中 Row Buffer**：很快，大概 10-20ns
- **没命中（要切换行）**：很慢，50-100ns 起步

#### 内存控制器的调度偏好

**关键的是**：内存控制器会**优先调度 Row Buffer 命中的请求**！

这个调度策略叫 FR-FCFS（First-Ready, First-Come-First-Serve），听起来挺公平，但实际上：

- **MATLAB 做矩阵运算**，内存访问很连续，Row Buffer 命中率高 → 请求总能插队
- **GCC 编译代码**，到处是指针、链表，访问很随机，命中率低 → 请求一直被延后

结果就是 MATLAB 的请求总是优先被处理，GCC 只能在旁边干等着，所以慢成了 3 倍。

> 这就是为什么**内存访问模式**对性能影响很大！同一台机器，程序写法不同，性能可能差好几倍。就像数组，在缓存的影响下综合性能也不一定就比链表查

## 三、DRAM 刷新问题

### 为什么需要刷新？

DRAM 用电容存数据，但电容会漏电。标准要求**每 64ms 必须把所有行刷新一遍**，不然数据就丢了。

### 老师的担忧（2015年视角）

老师说：**如果内存增大到 64GB，刷新时间将占到 46%！**

当时的逻辑是这样的：

- 容量越大 → 行数越多 → 刷新次数越多 → 占用时间越多
- 2GB 大概 1-2%，4GB 大概 8%，照这个趋势 64GB 就要 46% 了

### 现在的情况

我查了一下，2015年之后工业界搞了大量优化：

| 优化技术                          | 具体优化                     |
| ----------------------------- | ------------------------ |
| **Per-bank Refresh**          | 刷新一个 bank 时，其他 bank 照常工作 |
| **Temperature Compensated**   | 温度低的时候少刷新一点              |
| **Fine Granularity Refresh**  | 把刷新切得更细，减少单次阻塞时间         |
| **Refresh Management (DDR5)** | 智能按需刷新                   |

现在实际开销大概也就 **3-5%** 左右。我们日常用几十 GB 内存，体感上确实和以前 8GB 没啥区别，甚至因为性能高反而更快。

> **老师说的没错**——按当时的技术趋势，确实会很糟糕。但工业界意识到问题后积极优化，解决了这个问题。这也算是学术研究推动工业进步的一个好例子吧。

## 四、总结一下

这节课主要讲了几个点：

1. **好的架构师要理解底层原理，然后做权衡**
2. **内存控制器调度偏好 Row Buffer 命中**，所以不同访问模式的程序一起跑，可能互相影响很大
3. **DRAM 刷新确实有开销**，但现代技术已经优化得很好了
4. **学架构要学原理**，具体数字会随技术演进而变化——比如这门 2015 年的课，原理都对，但有些数据得自己更新一下
